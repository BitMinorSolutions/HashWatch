HashWatch for Mac · Powered by Bitminor
=======================================

UPDATING FROM 0.5
Quit the old HashWatch first (menu bar hexagon icon > Quit, or Activity Monitor >
HashWatch > Quit), delete HashWatch from Applications, then install this one.
From 0.5.1 on, HashWatch never uses a port another program is using, so it can't
open some other app's page by mistake. Other software on your Mac is never touched.

INSTALL
1. Open HashWatch.dmg and drag HashWatch onto the Applications folder.
2. Eject the disk image, then open HashWatch from Applications (or Launchpad).
   If you open it straight from the disk image, it offers to move itself to Applications.

FIRST LAUNCH: "Apple could not verify HashWatch"
HashWatch isn't notarized by Apple yet, so macOS blocks the first launch.
The easiest way: in Finder, Control-click (or right-click) HashWatch, choose Open,
then click Open in the dialog. You only need to do this once.

Or, if you already double-clicked it and saw the warning:
   - Click Done.
   - Open System Settings > Privacy & Security.
   - Scroll to Security and click "Open Anyway" next to HashWatch.
   - Click Open Anyway again and confirm with your password or Touch ID.

ALLOW LOCAL NETWORK
When macOS asks "Allow HashWatch to find devices on local networks?", click Allow.
HashWatch needs it to read your miner (port 4028). If you clicked Don't Allow:
System Settings > Privacy & Security > Local Network > turn HashWatch on.
Allow notifications too if you want alerts as Mac notifications.

USING IT
- HashWatch opens in its own window. Closing the window keeps it running in the
  menu bar (the hexagon icon at the top right): live hashrate, Open Dashboard,
  Share my dashboard on/off, Quit.
- Quit fully: HashWatch menu > Quit HashWatch (Cmd-Q), or the menu bar icon > Quit.
- Settings: HashWatch menu > Settings (Cmd-,).

RUNS SEPARATELY FROM OTHER MINER DASHBOARDS
HashWatch is fully independent of any other dashboard on the same Mac or network
(for example another dashboard reading the same Nano 3):
- Its own port (48412, or the next free one). It never uses a port another program
  answers on and checks that its own address really reaches HashWatch.
- Its own folder: ~/Library/Application Support/Hashwatch. Nothing else is read or written.
- Share uses HashWatch's own copy of cloudflared in that folder and its own
  tunnel. It never touches, reuses or stops any other cloudflared or other program.
- Installing HashWatch never changes your miner. The work speed schedule, backup
  pool failover and the light effects (block-found gold flash, status lamp,
  best-share flash) are all OFF until you turn each one on in Settings.
- HashWatch never changes the work speed because of heat (the Nano has its own
  overheat protection). "Running hot" is an alert only: it compares the average
  chip temperature to the miner's own target (90 °C if it reports none), with a
  2 °C allowance so normal regulation does not fire. A separate safety alarm
  fires if any chip stays at or above 95 °C. HashWatch never restarts the miner.
- The only settings HashWatch can ever send are work speed Low/Medium/High, the
  light colour, a Fan setting of Auto or a fixed 40–100% (Nano 3S, Mini 3 and
  Avalon Q; hidden on the original Nano 3), and — only if you turn on backup pool
  failover — switchpool among pools already set on the miner (never changing
  addresses or passwords). Anything else is refused before it leaves your
  computer. switchpool has not been tried on a real Nano 3 yet.
- Gentle on the miner: one connection at a time, short timeouts, a read every 5 s
  and slower (15 s, then 30 s) if the miner stops answering, so another dashboard
  can poll the same miner at the same time.

SOMETHING WRONG?
Settings > Copy debug info, then paste it into a message to us. It includes the
app and macOS versions, the miner's raw replies and recent errors; passwords are
removed. See TESTING.md for what to try.
